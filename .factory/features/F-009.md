# F-009: Announce every move and result through the live region

- **Milestone:** M3 · **Size:** S · **Requirements:** R-008 · **Depends on:** F-007
- **Screens:** game-02 and game-03 (the "Screen reader hears" annotations)
- **Components:** announcer, a visually hidden `role="status"` region
- **Branch:** `factory/F-009-announcements`, stacked on `factory/F-008-keyboard-and-focus` (PR #9)

## Acceptance criteria

1. Given each situation A1–A3 and A5–A8, when it occurs in Playwright, then the `role=status` region's text equals the exact string from acceptance.md. A4 is unreachable in the product and is covered at unit level by F-005.
2. Given any board state, when the squares are inspected, then each accessible name is "Row R, column C, empty|X|O". This is already done in F-006; here it is re-asserted after announcements.
3. Given a human move, when the computer replies, then the region is written once with a single message covering both moves. Given the same taken square twice, then the message is announced twice: the region is cleared, then set.

## Modules

- **`index.html`:** a `div#announcer.visually-hidden[role=status]` inside `main`, present from load and empty.
- **`src/ui/announcer.ts`:** `createAnnouncer(element)` returns `{ announce(text) }`. For a non-empty text it clears the region, then sets the text on the next animation frame, cancelling any pending frame. An empty text does nothing, so a `not-playing` step or the initial load announces nothing.
- **`src/main.ts`:** after every step, `announcer.announce(describeEvents(step.events))`.
- **`src/styles.css`:** `.visually-hidden` uses the clip-path pattern, not `display: none`, so screen readers still read it.

## Tests to write first

- **`tests/unit/announcer.test.ts`:** a fake element and fake `requestAnimationFrame`/`cancelAnimationFrame`, passed in through an options parameter. Checks:
  - `announce("A")` clears, then sets "A" on the next frame.
  - Two quick calls end with only the second text.
  - `announce("")` changes nothing.
- **`tests/e2e/announcements.spec.ts`** (all 5 projects, real games):
  - Exact region text for:
    - A1: You go first
    - A2: Computer goes first, "…row 1, column 1…"
    - A3: X at 0, O at 4
    - A5: the 3b draw
    - A6: the 3a win
    - A7: the computer-first draw, human 4, 2, 3, 7
    - A8: taken square 4
  - The region has `role="status"`, is visually hidden (1×1 clip, not `display: none`), and is empty on a fresh load.
  - **One update per action:** a `MutationObserver` installed before the action counts non-empty text values written to the region. A move gives exactly 1.
  - **Repeated A8:** activating the same taken square twice yields two non-empty writes with the A8 text.
  - After the announcements, the accessible names of all squares still match their content.

## Approach

It is one module with an injectable clock (animation-frame functions), so the timing is unit-testable. All text comes from `describeEvents` (F-005); nothing here builds strings.
