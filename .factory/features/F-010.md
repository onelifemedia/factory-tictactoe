# F-010: Verify WCAG 2.2 AA, responsive layout and a stable board

- **Milestone:** M3 · **Size:** S · **Requirements:** R-009, R-010, R-013 · **Depends on:** F-008, F-009
- **Screens:** game-01, game-02, game-03 (page layout: reserved status and action heights)
- **Branch:** `factory/F-010-accessibility-and-layout`, stacked on `factory/F-009-announcements` (PR #10)
- **New dev dependency:** `@axe-core/playwright` 4.13.0 (MPL-2.0; axe-core 4.13.0, MPL-2.0). It is test-only, never shipped, and was license-checked at inception (`tech-stack.md`).

## Acceptance criteria

1. Given each state (choice, in play, computer won, draw), when axe-core runs with the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa` in Chromium, Firefox and WebKit, then there are 0 violations.
2. Given the 320×568, 390×844 and 1280×800 viewports, when each state is shown, then `scrollWidth` does not exceed the viewport width and every square and button is at least 44×44 CSS px.
3. Given 320×568 and 1280×800 at default text size, when moving through choose, play (with the taken message and the longest status) and game over, then the board's bounding box is identical.
4. Given `tokens.json`, when a unit test computes contrast, then every text pair is at least 7:1 and every non-text indicator at least 3:1 (R-013's house rule, above AA).
5. The page has `lang`, a descriptive `<title>`, one `h1`, and the board is exposed as a labelled group (R-009; the F-001 shell test covers the first three, and this feature adds the group).

## Tests to write first

- **`tests/e2e/accessibility.spec.ts`:** `AxeBuilder` with the five tags, run in the 4 states in every project (the criterion names the 3 desktop engines; the 2 mobile projects are run too at no extra cost). A violation fails with its ids and targets listed. The board is `getByRole("group", { name: "Board" })`.
- **`tests/e2e/layout.spec.ts`:**
  - For each of the 3 viewports and 4 states: `documentElement.scrollWidth` ≤ `innerWidth`, and every `.square` and `button` bounding box is at least 44×44.
  - **Board stability** at 320×568 and 1280×800: record the board's box on the choice screen, then after "You go first", after a taken-square message, after the longest continuing status ("Computer placed O in row R, column C. Your turn. You are X." when the computer starts), and after the longest result ("Computer wins with the diagonal from top right to bottom left."). All must be equal (a 0.5 px tolerance for sub-pixel rounding).
- **`tests/unit/contrast.test.ts`:** the WCAG relative-luminance contrast of each pair from `design-system.md` §2, computed from `tokens.json`:
  - Text pairs, at least 7:1: text on surface, text on surface-sunken, text on win-surface, text-muted on surface, on-primary on primary.
  - Non-text pairs, at least 3:1: border on surface, border-disabled on surface-sunken, focus on surface, focus on surface-sunken, primary on surface, win-marker on win-surface.

## Approach

This is a verification feature. Only layout or markup that the tests prove wrong gets changed; any such change is recorded under "Deviations" with its cause. The contrast function lives in the test (no production code needs it).

## What was built

This feature only adds tests; no production code changed, so there are no deviations. The behaviour was already right: every test passed on its first run. Each check was then proven able to fail by a mutation:

| Check | Mutation | Result |
|---|---|---|
| Board stability | status line with no reserved height | fails at 320 × 568 |
| Contrast | text-muted set to #8a8a8a | 1 failure |
| axe | an unlabelled button added | `button-name` violation |
| Required targets (round 1, C1) | disabled squares `visibility: hidden` | 7 failures |
| Targets on screen (round 1, C2) | squares translated off screen | 6 failures |
| Opacity (round 2, C1) | `opacity: 0` | 3 failures |
| 200% text (round 2, C2) | status clipped | fails in the longest-message state |

Test files:
- `tests/e2e/accessibility.spec.ts`: axe with the 5 WCAG tags in 4 states × 5 projects. The full "incomplete" results are attached as JSON.
- `tests/e2e/layout.spec.ts`:
  - 4 viewports, including 640 × 400 (the CSS-pixel size of 1280 × 800 at 200% zoom), × 4 states.
  - Required targets (9 squares plus each state's buttons) must be visible with effective opacity above 0, inside the viewport, and at least 44 × 44.
  - Board stability at 320 × 568 and 1280 × 800.
  - 200% root text (all type sizes are rem) with a clipping check.
- `tests/e2e/game-states.ts`: the 4 shared states.
- `tests/unit/contrast.test.ts`: 14 tests.

Totals: 286 unit and 355 e2e runs, all passing.

## axe "incomplete" disposition

axe reported **no** incomplete rules in any state or project (recorded per test as an annotation and attached JSON), so nothing needed manual review. This is the automated gate only. The VoiceOver and real-device checks stay **not performed**, as human follow-up (intent).
