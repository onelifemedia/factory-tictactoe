- **Milestone:** M1 · **Size:** M · **Requirements:** R-013, R-015
- **Screens:** `design/screens/game-01-choose-first.html` (page shell only: lang, title, h1, main; the rest comes in F-006/F-011)

## Acceptance criteria

1. Given a fresh clone with Node 22, when `npm ci` and `npm run build` run, then `dist/` contains `index.html` and one JS bundle built with target `es2022` and base `./` (relative asset URLs).
2. Given the repo, when `standards.sh check` runs, then it passes: Prettier format check, ESLint with the standards §6 naming recipe (warnings as errors), `tsc --noEmit` strict, Vitest, git hooks in `.githooks` (pre-commit: format_check; pre-push: format_check, lint, typecheck, test), and CI running the same commands.
3. Given the built page served by `vite preview`, when Playwright loads it in all five projects (chromium, firefox, webkit, mobile-android, mobile-iphone), then it has `lang="en"`, the title "Tic-tac-toe: play against a computer that never loses", one `h1` "Tic-tac-toe", a `main` landmark, and a body `font-family` beginning with `system-ui`.
4. Given `src/styles.css`, when it is read, then every design token in `.factory/design/tokens.json` is defined as a CSS custom property with the same value (mapping below).
5. Given a push or pull request, when CI runs, then format check, lint, typecheck, unit tests, build and the Playwright suite all run and pass.

## Tests to write first

- `tests/unit/tokens.test.ts` (F-001): reads `.factory/design/tokens.json` and `src/styles.css`, parses the `:root` block's custom-property declarations, and asserts that for every string or number leaf a property exists whose value is **equivalent**: whitespace collapsed, and single and double quotes treated as the same, because Prettier rewrites quotes and wraps long values (Codex spec review C1). Mapping:
  - `color.light.<key>` → `--color-<key>`
  - `font.family` → `--font-family`
  - `font.size.<key>` → `--font-size-<key>`
  - `font.line.<key>` → `--font-line-<key>`
  - `font.weight.<key>` → `--font-weight-<key>`
  - `space.<key>` → `--space-<key>`
  - `radius.<key>` → `--radius-<key>`
  - `size.<key>` → `--size-<key>`; nested leaves are flattened, e.g. `size.status-min-lines.narrow` → `--size-status-min-lines-narrow`. They are defined now and used by later features.
  - `a11y.<key>` → `--a11y-<key>`
  - `motion.<key>` → `--motion-<key>` (`--motion-fast: 0ms`)
  - Excluded, enumerated explicitly: keys starting with `$` (comments); `version`; `shadow` (an empty object); `breakpoint` (descriptive strings used as media-query literals, not CSS values).
- `tests/unit/hooks.test.ts` (F-001):
  - `.githooks/pre-commit` and `.githooks/pre-push` exist, are executable, and invoke the configured commands (pre-commit: format_check; pre-push: format_check, lint, typecheck, test).
  - `package.json` `prepare` sets `core.hooksPath` to `.githooks`.
  - Running each hook with a stub `npm` on `PATH` that exits 1 makes the hook exit non-zero (the hook blocks the Git operation).
- `tests/e2e/shell.spec.ts` (F-001), run in all five projects:
  - the `html` element has `lang="en"`
  - the document title is exact
  - exactly one `h1`, with text "Tic-tac-toe"
  - one `main` element
  - the computed body `font-family` starts with `system-ui`
  - no console errors or page errors during load

## Approach

Vite with vanilla TypeScript, no framework (ADR-001):
- **Build:** `vite.config.ts` sets `base: "./"` and `build.target: "es2022"`. `vitest.config.ts` runs `tests/unit/**/*.test.ts` in Node.
- **Playwright:** `playwright.config.ts` builds, then serves `vite preview` on port 4173. It defines the five projects of ADR-008 (Desktop Chrome, Desktop Firefox, Desktop Safari, Pixel 7, iPhone 14) with `tests/e2e`.
- **Linting:** `eslint.config.js` is the standards §6 recipe verbatim. JavaScript config files are **not** exempted with `disableTypeChecked`, which would also switch off the naming rules (Codex C3). Instead `tsconfig.json` sets `allowJs` and includes them, so `projectService` lints them with the full recipe. It ignores `dist`, `.factory`, `playwright-report` and `test-results`, and runs with `--max-warnings 0`. Prettier uses its defaults and ignores `.factory`, `dist` and the lockfile.
- **Standards commands:**
  - `format_check` = `npm run format:check`
  - `lint` = `npm run lint`
  - `typecheck` = `npm run typecheck`
  - `test` = `npm test`, where the `test` script is `vitest run` (never watch mode). It runs Vitest only; the Playwright suite is too slow for pre-push, and CI runs it as a separate job.
- **Hooks and CI:** `standards.sh install` renders the hooks, and `prepare` sets `core.hooksPath`.
  - `ci.yml` job `checks`: checkout, `setup-node` with `node-version-file: .nvmrc` and npm cache, `npm ci`, assert `git config core.hooksPath` = `.githooks`, then the four commands and `npm run build`.
  - Job `e2e`, self-contained: checkout, the same Node setup, `npm ci`, `npx playwright install --with-deps chromium firefox webkit`, and `npm run test:e2e` with no project filter.
- **Tokens and page:** `src/styles.css` defines the tokens under `:root` using the mapping above, plus body base styles (`font-family: var(--font-family)`, text and surface colours). `index.html` has only the shell; `src/main.ts` only imports the stylesheet.
- **Node version:** `.nvmrc` = `22.23.3` (exact, used by both CI jobs). `engines.node` = `>=22.13.0 <23`: ESLint 10 and unicorn 76 need at least 22.13.0 (Codex C4).
- **TypeScript coverage:** `tsconfig.json` includes `src`, `tests`, and the root `*.ts`/`*.js` configs (`allowJs`, `checkJs: false`), with `strict`, `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` (ADR-006).
