## Verdict
AGREE-WITH-CONCERNS
The static-then-motion split and requirement tracing are sound, but contradictory acceptance criteria and test dependencies need correction.

## Findings
- [C1] [HIGH] F-014 contrast acceptance — Requiring every listed non-text pair to reach 3:1 contradicts the approved palette — design-system.md §2 explicitly lists border on tile-edge as **2.56:1**, with a boundary rationale — Enumerate threshold-tested pairs separately from documented ratios, preserving that explicit exception.
- [C2] [HIGH] F-014 `tests_first`, check-local-visuals.test.ts — Testing the real `dist/` inside the unit suite introduces an unmet build dependency — `.github/workflows/ci.yml:28–29` runs `npm test` before `npm run build` on a fresh checkout — Keep unit tests fixture-only; verify the real build through the already-planned post-build CLI step.
- [C3] [MEDIUM] F-015 view-new-pieces.test.ts — The proposed render unit test lacks a DOM test environment — `vitest.config.ts` specifies `environment: "node"`, while `src/ui/view.ts:45` calls `document.createElement`; package.json has no DOM emulator — Either plan the environment dependency/configuration, or unit-test a pure board-difference helper and verify actual rendering in Playwright.
- [C4] [MEDIUM] F-015 acceptance and `tests_first` — Normal-motion press/hover behavior is insufficiently specified and tested — design-system.md §4 requires an 80 ms press for tiles **and buttons**, a 1 px empty-tile hover rise, and a drop from −22 px at 1.15× scale; the plan tests drop duration but omits those geometry checks and normal-motion button presses — Add concrete assertions for those effects and for occupied/disabled tiles ignoring hover and press.
