## Verdict

AGREE-WITH-CONCERNS

The approach is workable, but the pinned linter rejects its concurrency syntax, and essential deployment dependencies and rollback protection remain unspecified.

## Findings

- [C1] [HIGH] **Workflow lint** — actionlint 1.7.12 rejects `queue: max` — its `parseConcurrency` accepts only `group` and `cancel-in-progress`, reporting other keys as errors ([source](https://github.com/rhysd/actionlint/blob/v1.7.12/parse.go#L755-L776)) — use a version verified to support `queue`, or narrowly suppress that diagnostic while independently validating the concurrency block.
- [C2] [HIGH] **Jobs 1–5 and static tests** — the dependency graph and stale-run gate are missing — numbered jobs do not establish execution order; jobs run in parallel unless `needs` is specified, and `needs` exposes only direct dependencies ([syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idneeds), [contexts](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#needs-context)) — specify `build.needs: prepare` with `should_deploy == 'true'`, `deploy.needs: build`, `smoke.needs: [prepare, deploy]`, and `rollback.needs: [deploy, smoke]`; require successful deploy plus failed smoke under `always()`. Test these relationships, including stale and failed-build cases.
- [C3] [MEDIUM] **Rollback environment** — only `deploy` targets `github-pages`; rollback does not inherit that job’s environment or protection — Pages deployment authorization uses job-specific OIDC context ([deploy-pages documentation](https://github.com/actions/deploy-pages#security-considerations)) — explicitly target `github-pages` from rollback and document protection settings compatible with unattended rollback; required human approval would defeat automatic recovery.
- [C4] [MEDIUM] **Smoke polling** — a 180-second polling limit does not extend Playwright’s enclosing test timeout — the default test timeout is 30 seconds, so propagation taking 45 seconds would cause premature failure and rollback ([Playwright documentation](https://playwright.dev/docs/test-timeouts)) — specify a test timeout exceeding polling plus gameplay, and test delayed build-id availability beyond 30 seconds.
- [C5] [MEDIUM] **`select-rollback-run` and workflow tests** — matching job names is sound only with a stable naming contract; checking YAML job IDs alone does not establish it — the jobs API returns `name`, while its numeric `id` is an execution identifier ([API schema](https://docs.github.com/en/rest/actions/workflow-jobs#get-a-job-for-a-workflow)) — explicitly freeze display names as `deploy` and `smoke`, assert them in workflow tests, and use fixtures shaped like actual API responses.
- [C6] [MEDIUM] **Rollback history lookup** — pagination is unspecified — the runs API defaults to 30 results; 30 intervening skipped/failed runs can hide an eligible, unexpired artifact ([API documentation](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-workflow)) — paginate until an eligible run is found or history is exhausted, and test a candidate beyond page one.

## Missing

- Specify checkout, dependency installation, and SHA/URL environment wiring for the separate smoke job.
- Carry the accepted 100-pending-run limit into acceptance criterion 2; “none is discarded” is currently unconditional.
