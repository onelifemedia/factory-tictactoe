The approach is workable, but the smoke test targets the wrong URL on the first real deployment, and CI eligibility and rollback history have correctness gaps.

## Findings

- [C1] [HIGH] `tests/smoke/smoke.spec.ts:62` — `page.goto("/")` discards the Pages project path — with `SMOKE_URL=https://onelifemedia.github.io/factory-tictactoe/`, it visits `https://onelifemedia.github.io/`, so a healthy deployment fails smoke and triggers rollback; the root-only harness misses this ([Playwright URL semantics](https://playwright.dev/docs/api/class-testoptions#test-options-base-url)) — navigate to the complete configured URL and add a harness case served exclusively beneath `/factory-tictactoe/`.
- [C2] [MEDIUM] `.github/workflows/deploy.yml:56–57`; `scripts/deploy/resolve-dispatch-sha.mjs:15–17` — manual dispatch can accept PR CI while main’s CI is pending or failed — the query filters only by SHA, discards event/branch metadata, and accepts any success; an executed fixture containing a successful PR run and an in-progress main push run for the same SHA returned `{ sha }`, violating criterion 3 — filter CI runs by `event=push&branch=main` as well as SHA, and test this mixed-event case.
- [C3] [MEDIUM] `scripts/deploy/find-rollback-run.mjs:33` — pagination cannot exhaust the promised history — GitHub caps searches using `branch` or `status` at 1,000 results; an unexpired good deployment behind 1,000 skipped/failed runs remains unreachable despite additional pages ([API limit](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-workflow)) — paginate unfiltered workflow history and filter locally, or partition searches into bounded creation-time windows; test beyond 1,000 candidates.
