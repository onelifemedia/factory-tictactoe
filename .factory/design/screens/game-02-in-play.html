Mockup: 2. In play

The board is active and it is always the human's turn when idle, because the computer replies instantly. Traces to R-001, R-002, R-003, R-007, R-008, R-009 and R-010. Exactly one square is in the Tab order, and arrow keys move between squares. The visible status names the computer's last move so sighted players can find it. A keyboard hint in the action area is linked to the board with aria-describedby. Sample positions come from the actual perfect-play rules (ADR-010).

2a. You went first: empty board

After choosing “You go first”, focus moves to the first empty square (row 1, column 1).

Phone, 320 px wide

Tic-tac-toe

Your turn. You are X.

Arrow keys move between squares. Enter or Space places X.

New game. You go first. You are X. Your turn.
Screen reader hears (live region, not visible):A1: “New game. You go first. You are X. Your turn.”

2b. Computer went first: O opens

The computer always opens at row 1, column 1 (ADR-010). O opening is intended. Focus goes to the first empty square, row 1, column 2, so the first Enter doesn't hit a taken square.

New game. Computer goes first as O. Computer placed O in row 1, column 1. Your turn.

2c. Mid-game after a move

You: row 1, column 1; computer: row 2, column 2. You: row 3, column 3; computer: row 1, column 2 (the correct reply to opposite corners). Focus stays on the square just played.

2d. Taken square

The player activated row 2, column 2, which already holds O. Nothing changes on the board. The status line shows the message until the next valid move replaces it; moving focus does not clear it.

Phone, 320 px wide

Tic-tac-toe

Row 2, column 2 is taken. Choose an empty square.

Arrow keys move between squares. Enter or Space places X.

Row 2, column 2 is taken. Choose an empty square.
Screen reader hears (live region, not visible):A8: “Row 2, column 2 is taken. Choose an empty square.” The announcer is cleared and then written on every action, so pressing the same taken square twice is announced twice.
